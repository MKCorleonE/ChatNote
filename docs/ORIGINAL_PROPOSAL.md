# CodexAnnotation：带批注追问的学习对话

当前阶段：已有深色英文桌面交互原型，并于 2026-10-06 提交功能建议 [openai/codex #51373](https://github.com/openai/codex/issues/51373)。原型仍使用预设回答，尚未接入模型。提交结果见 [ISSUE_SUBMISSION.md](../ISSUE_SUBMISSION.md)。

分享演示：[CodexAnnotation-demo.zip](../CodexAnnotation-demo.zip)。接收者解压后用现代浏览器打开 `CodexAnnotation-demo.html`。该文件包含全部样式和脚本，无需安装或启动服务；本地保存取决于浏览器权限。包内没有浏览器配置或用户保存记录。

原型入口：[prototype/index.html](../prototype/index.html)。Windows 独立窗口启动入口：[prototype/Launch-Prototype.cmd](../prototype/Launch-Prototype.cmd)。体验方式与验证记录见 [prototype/README.md](../prototype/README.md)。

## 要解决的问题

学习 Transformer 等复杂知识时，用户希望沿着一条主线学习，同时就原文中的名词、公式或段落追问。把所有追问追加到主聊天会打断主线；把追问放进独立聊天又容易丢失原文位置和关联。

项目目标：让追问成为绑定到原文的、可持续对话的批注。阅读主线时可折叠，复习时可展开，并可查看追问树。

## Transformer 示例

- 主线：总体结构 → Q/K/V → 注意力权重 → 多头注意力 → 前馈网络。
- Q/K/V 段落上的批注：为什么 Q 和 K 要使用不同的投影矩阵？
- 批注中的再次追问：如果共享矩阵会有什么限制？
- 缩放点积段落上的批注：为什么除以 √d_k？

每条追问都有明确来源，主线仍按教学顺序排列。

## 建议交互

1. 在助手回答中选中词语、公式或段落，选择“批注追问”。
2. 右侧打开一个追问面板，显示引用原文、问题和回答。
3. 在同一面板继续追问；选中批注回答中的内容，也可以建立下一层批注。
4. 原文保留高亮和批注数量。悬停或键盘聚焦显示简短预览；点击打开完整对话。触屏使用点击。
5. 主聊天输入框继续主线。批注输入框只更新当前旁支。
6. 复习时切换到追问树，点击节点回到原文或对应回答。
7. 用户可明确选择“将结论加入主线”，以简短摘要带回主聊天。

悬停用于预览，不承载完整长回答；完整回答支持固定打开，避免鼠标移动后消失。

## 第一版范围

先用固定的 Transformer 示例回答验证交互，再接入真实模型。

- 支持主线聊天与任意文本选择。
- 支持原文锚定、高亮、批注面板和旁支连续追问。
- 支持批注回答上的子批注。
- 保存主线、批注、原文位置及父子关系；重新打开后恢复。
- 显示可折叠的追问树，支持节点定位。
- 导出完整结构数据，以及含原文引用的可读笔记。

第一版验收场景：在 Q/K/V 和缩放点积两段分别建立追问，为其中一条创建子追问，关闭并重新打开后，所有关联仍可定位；主线消息数量和教学顺序不因旁支追问而改变。

暂缓跨设备同步、多人协作、自动知识图谱，以及直接改造官方桌面聊天界面。

## 关键设计

### 原文锚定与版本

锚点保存消息 ID、回答版本、选中文字、文本起止位置和前后文。起止位置针对稳定的原始文本计算，不依赖页面坐标或临时网页节点。

回答重新生成时保留旧版本，批注仍绑定旧版本。若未来允许修改正文，应尝试重新定位；匹配不唯一时显示“待重新关联”，由用户选择新位置，不能静默绑定到错误内容。

公式、代码、列表和跨段落选择需要分别验证。可以先支持单段落选择，再扩展复杂选区。

### 旁支上下文

批注追问默认获得：学习目标、截至锚点的必要主线摘要、被引用的原文和周边内容、当前旁支历史。

不默认携带其他旁支；也不默认把旁支完整历史追加到主线。是否把有用结论带回主线由用户明确决定。

保存创建旁支时的上下文快照，避免后来主线的发展让同一批注的上下文含义悄悄改变。较长旁支需要独立摘要和长度管理。

### 追问树与知识图谱

第一版展示真实发生过的追问父子关系，节点标题可以生成，但引用和关联以存储记录为准。

追问树不等于知识图谱。例如“线性投影”可能被多个章节引用，属于跨分支概念关系。知识图谱可后续增加，但不应让模型生成的概念关联替代真实追问记录。

### 数据结构建议

- LearningSession：学习主题、学习目标与主线。
- Message：所属对话、角色、正文和回答版本。
- Annotation：来源消息及版本、原文锚点、所属旁支。
- Branch：父批注或父旁支、连续问答、创建时上下文快照。

同一处原文允许多个批注；同一旁支允许多轮问答；子批注可以定位到批注中的回答。

## 可选实现路线

| 路线 | 适用目标 | 主要约束 |
| --- | --- | --- |
| 独立学习客户端 | 完整验证主线、批注与复习体验 | 自己维护界面、存储与模型接入 |
| 基于 Codex App Server 的客户端 | 复用公开的 Codex 会话与事件协议 | 需要验证旁支上下文、认证和实际协议能力；批注关系由本项目管理 |
| 浏览器扩展 | 尝试覆盖网页中的既有聊天 | 页面变化和历史加载影响锚定；模型调用与会话关联仍需单独处理 |
| 官方原生功能 | 直接改善 ChatGPT/Codex 的既有体验 | 需要产品团队实现或提供明确界面扩展能力 |

建议先做独立交互原型，再确定模型接入方式。公开的 App Server 能作为自建客户端的底层，不代表能向官方桌面界面直接插入控件。
