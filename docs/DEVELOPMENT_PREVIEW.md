# ChatNote 开发预览

当前正式版本仍为 v0.5.0。开发预览运行本地最新源码，不生成安装包、不替换已交付 exe，也不自动发布版本。

当前已加入 [对话界面微调](PREVIEW_CHAT_REFINEMENTS.md)：自适应青色气泡、提问复制/编辑重发/时间、回答图标复制，以及旧来源保留的历史切换。其检查和用户验收状态单独记录，正式 v0.5.0 exe 不包含这些改动。

最新微调：提问操作和回答时间在悬停/键盘聚焦时显示，回答只保留复制与上下文图标，完成统计已删除。时间按今天/本周星期/较早月日显示，图标随阅读字号缩小并同步变化。

## 双击入口

1. 关闭正在运行的 ChatNote 正式版或其他开发预览窗口，无需退出账号。
2. 双击项目根目录的 [启动开发预览.cmd](../启动开发预览.cmd)。
3. 等待完整的 ChatNote 桌面窗口打开。首次启动需要编译开发程序，可能等待数分钟。
4. 使用期间保留启动时打开的命令窗口。界面、文案和样式修改通常自动刷新；底层功能修改会触发重新编译和应用重启。
5. 用完关闭 ChatNote，在命令窗口按 Ctrl+C 结束开发服务；若提示是否终止批处理，输入 Y。下次继续双击入口。

该入口需要本机已有 Node.js/npm、Rust/Cargo、Windows C++ 构建工具、WebView2 和项目依赖。缺少工具、ChatNote 已打开或预览端口 1420 被占用时，启动入口会显示错误并停下，不自动关闭其他程序。

## 数据与版本

- 默认沿用正式版的应用标识、SQLite 工作区和系统凭据库，现有聊天、批注、草稿、连接和登录可以继续使用；不复制示例覆盖工作区，不主动重新登录或退出。
- 预览期间的聊天和设置操作会写入同一工作区。涉及数据格式或存储功能的改动，先使用应用的完整工作区备份，再进行实际数据验证。
- 维护者可以通过现有 `CHATNOTE_DATA_DIR` 环境变量使用独立测试数据库；该变量不会隔离系统凭据库，不应将其当作账号隔离功能。
- 开发窗口里的版本号暂时仍显示 v0.5.0，以本地源码和未发布记录识别改动。开发预览不能作为 v0.5.0 正式交付文件已包含新功能的证明。
- 小改动逐项保存与验证，积累后统一更新正式版本、相关文档与安装包；每次代码提交不必对应一次发布。

`prototype/Launch-Prototype.cmd` 是早期演示，不能用于预览当前完整应用。`npm run dev` 仅提供浏览器界面预览，桌面登录和模型调用需要这里的桌面入口。
