# ChatNote v0.2.1 · 登录超时恢复与私有版本管理

日期：2026-10-08。

## 已实现

- 等待浏览器授权时提供“取消登录”，关闭本次等待与回调监听后可重新尝试，无需等待完整三分钟。
- 取消/超时说明提示关闭旧授权页、检查浏览器是否可访问 ChatGPT，保存的原注册和聊天保持完整。
- 手动“检查登录连接”只请求官方公开登录服务信息，不发送令牌、聊天或推理请求，不消耗模型生成额度。检查有连接和总时间限制；客户端检查成功也不保证浏览器授权页正常。
- 普通重新登录继续复用原注册 client ID 与 host ID；没有用重新注册替代正常退出/重登，没有改成自动 API 计费。
- 使用实际程序版本作为网络 User-Agent。
- 初始化本地 Git/main 与 v0.2.0 源码基线，建立并推送 MKCorleonE/ChatNote 私有仓库。新增忽略规则、换行规则、开发发布约定及 GitHub Actions 检查。

## 本轮验证

- 28 项前端/数据/UI 测试、13 项常规 Rust 测试通过，共 41 项。两项写入系统凭据库的测试保持显式忽略，本轮未执行。
- 受控测试验证取消→释放等待→再次登录、保留配置、手动连接检查不调用生成或登录，原生取消状态不会带到下一次尝试。
- TypeScript/Vite 编译、Windows release 和 NSIS 安装包构建完成；Vite 大资源包提示仍待优化。
- GitHub 私有性、远程提交/标签与 Release 附件完整性单独检查。云端自动检查的状态以 Actions 实际结果为准，不用本地测试结果替代。

## 用户反馈与网络证据

用户报告：退出套餐账号后，浏览器里的 OpenAI 授权页提示 Operation timed out；随后再次尝试已可以登录。恢复发生在新版交付前，记录为用户重试恢复，不能声称由本版修复了服务端问题。

本机对官方公开登录地址的连通性检查曾出现 TLS 握手失败与超时，GitHub API 同时可达；本机已有代理路径也未通过。这个结果不能证明浏览器故障的具体根因。未禁用证书验证，未更改系统代理、删除注册信息或使用真实账号进行模型请求。

正常退出保留注册、重新登录复用原 client ID，符合[官方账号与会话说明](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)。

## 交付

新版真实升级安装、取消真实 OAuth 后重新授权仍待用户实测。Windows 内测包尚未签名，其他平台未交付。
