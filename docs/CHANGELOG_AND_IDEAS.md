# ChatNote 版本记录与待实现想法

更新：2026-10-08。

本文件记录正式版本、用户实际验证、未来版本建议和待实现想法。每次应用升级后必须同步本文件，并更新功能状态与交付说明；该约定已加入项目 AGENTS.md。

## 记录规则

- 已发布/已交付版本记录最终行为、验证证据和已知限制。
- 原型阶段不算正式应用版本，不把演示包版本与客户端版本混用。
- “已实现”“自动测试通过”“实际使用验证”分别记录；用户反馈注明来自用户，不扩展为未进行的测试。
- 未来版本号和范围是建议，讨论确定后再开始开发；未交付的内容不会写进已发布版本。
- 新想法使用稳定编号；完成后记录所属版本，继续保留历史。
- 每次版本发布补充变更、修复、数据迁移、测试和未完成项。

## 版本历史

### 原型阶段 · 2026-10-06 起

正式客户端版本号：无。

- HTML/CSS/JavaScript 深色桌面原型。
- 固定 Transformer 示例，主线聊天与原文高亮。
- 独立多轮批注、批注内子追问、追问树、来源定位。
- 浏览器本地保存与 Markdown 导出。
- 离线 HTML、视频和此前功能建议作为历史材料保留。
- 原型回答为预设内容，不属于真实模型调用。

- 从 CodexAnnotation 更名为 ChatNote。
- 确定独立软件方向、Windows 优先、预留五个平台。
- 沿用原型的主线与批注交互，弱化历史列表。
- 建立产品计划、功能清单及阶段验收。

### v0.1.0 · 2026-10-08 · Windows 内测版

交付：[安装程序](../releases/archive/v0.1.0/ChatNote_0.1.0_x64-setup.exe)、[直接启动程序](../releases/archive/v0.1.0/ChatNote.exe)。

**界面与交互**

- React / TypeScript 界面，Tauri 2 / Rust 桌面外壳。
- 窄导航栏、按需打开的历史抽屉，选中会话后自动收回。
- 主线与右侧批注/追问树；新建、切换、重命名和删除会话。
- 普通文本原文锚点、高亮重开、多轮批注和递归子批注。
- 回到父批注、跳到来源、阅读位置与草稿保存。
- 可预览编辑的结论带回主线，并保留来源。
- Markdown、基本公式和代码显示；深浅主题、字体大小、批注开关。

**模型与上下文**

- OpenAI Responses API、实验性 ChatGPT 套餐授权与模型目录。
- OpenAI-compatible provider 入口，使用 Chat Completions 协议。
- 流式输出、停止、失败状态、保留部分回答、作为新回答重试。
- 旁支保存来源快照，兄弟分支和后来的主线内容不自动加入。
- 可查看实际请求上下文；长记录以明确标记的摘录缩减，完整原文保留。
- 当前摘录不是语义摘要，字符预算也不是精确 token 预算。

**数据与交付**

- SQLite 事务、持续保存、重启恢复和最近旧快照。
- 系统凭据库保存密钥/令牌，普通备份不包含凭据。
- 兼容服务商密钥绑定 API 地址；单实例启动。
- Markdown 导出、完整工作区备份和非破坏性导入。
- Windows release 程序、NSIS 安装包、图标和校验值。
- 开发预览忽略桌面编译目录，避免监听正在使用的 DLL 导致退出。

**验证**

- 13 项界面/核心测试、8 项常规桌面测试、1 项单独执行的凭据库测试，共 22 项通过。
- 本机实际启动、单实例、原生导出、重启恢复会话/批注/草稿。
- 本机安装、同版本重装和卸载成功；独立测试数据库保留。
- 500 主线消息 + 500 批注的合成记录成功导入并切换追问树。
- 390×844 响应式布局检查；尚未等同于移动真机验收。
- 2026-10-08 用户反馈：ChatGPT 套餐已登录并可对话；这是交付后的实际使用补充，不回写为此前助手完成了真实账号测试。

**限制**

- 当前只有 Windows 内测交付，尚未签名；无云同步/自动更新。
- 真实 API Key、第二家厂商、套餐连接生命周期和长时间稳定性仍待测。
- 选区只开放能准确映射到原文的普通文本叶节点；跨段落、跨格式、代码/公式批注尚待实现。
- UI 当前仅英文；没有完整多语言体系或语义摘要。

详细证据：[BUILD_AND_VALIDATION.md](BUILD_AND_VALIDATION.md)。

### v0.1.1 · 2026-10-08 · 连接管理升级

本版由用户明确要求：先完成连接预设、独立保存、一键切换、状态/额度/错误提示；多语言与动画继续后置。

- 新增 DeepSeek、Qwen/百炼、OpenAI API 与自定义连接预设。
- 每个 API 连接分别保存名称、地址、模型和独立凭据；保存 metadata 后再写 Key。
- 主界面连接下拉框直接切换，Settings 支持选择使用和命名；不覆盖其他连接。
- 旧 OpenAI/兼容服务商/ChatGPT 配置自动迁移，不重置已有聊天或登录。
- 查询模型目录检查身份，保存检查结果/时间；不自动调用模型生成。
- DeepSeek 可主动查询实际余额；ChatGPT/Qwen/OpenAI 明确显示无法直接查询的边界和官方用量入口。
- 额度、限流、身份、模型/地址、权限、网络等错误分别给出恢复说明，保留脱敏详情。
- 新回答记录连接来源，失败不自动换收费通路。
- 33 项测试通过：20 前端/数据/UI、11 常规原生、2 显式安全存储测试。真实厂商模型/余额仍待用户账号实测。
- 实际预览验证添加、切换、刷新恢复及 390 px 窄窗口布局。

完成范围对应 I01/I02（预设）、I03（多连接）、I04（目录检查/错误说明）；它们的真实厂商验收继续保留待测项。详见 [v0.1.1 验证记录](V0.1.1_VALIDATION.md)。

## 服务商接入讨论 · 核对于 2026-10-08

API 是接入形式；Plan 是额度/计费安排。有些套餐仍使用专属 API Key，不能把“用 Key”与“用套餐”看成相反概念。

| 通路 | 当前判断 | ChatNote 建议 |
| --- | --- | --- |
| DeepSeek 官方 API | 官方提供 Key 与兼容协议 | 现有兼容入口可尝试；优先补配置预设与实测 |
| Qwen / 阿里云百炼普通 API | 支持 OpenAI Chat 接口；地域和业务空间决定地址 | 从控制台取得匹配的 Key、Base URL 和模型 ID |
| 阿里云 Token Plan | 使用专属 Key/地址；有产品版本及使用范围区别 | 评估具体订阅是否适用，再开发/标识套餐支持 |
| ChatGPT Plan | 用户已验证登录与对话 | 继续补生命周期与清晰的额度/连接状态 |

DeepSeek 当前首次调用文档使用 `https://api.deepseek.com`，列出 `deepseek-flash` 和 `deepseek-v4-pro`；模型 ID 后续仍应依据控制台/官方目录核对，不固定沿用旧别名。[DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/)

Qwen 普通 API 支持兼容接口。百炼目前有业务空间专属域名，各地域 Key 不通用；预设应支持控制台提供的地址，避免把一个旧地址固定用于所有用户。[百炼兼容说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)

Token Plan 团队版 FAQ 列出 Cherry Studio、Chatbox 等兼容工具；概述仍要求交互式工具使用，排除应用后端/自动化脚本。个人版也有使用范围限制。判断 ChatNote 是否适用时，需要核对具体套餐和交互方式；协议兼容不等同于已获得厂商认可。这里尚未得到厂商对 ChatNote 的明确确认。[团队版 FAQ](https://help.aliyun.com/zh/model-studio/token-plan-team-faq)、[团队版范围](https://help.aliyun.com/zh/model-studio/token-plan-team-overview)、[个人版范围](https://help.aliyun.com/zh/model-studio/token-plan-personal-overview)

当前可以在 Settings 选择 OpenAI-compatible provider，填写服务商自己的 Base URL、Key 与模型 ID。它具备尝试通路，但本轮没有替用户连接国内账号或调用模型，也没有验证思考内容、多模态和每家特殊参数。

## OpenAI 认证讨论

用户提供的授权页提示：

> 该智能体及其名称未经 OpenAI 认证。允许访问后，该智能体即可使用你的 ChatGPT 使用额度。
> 请仅向你信任的智能体授予访问权限。继续操作前，请查看下方的使用条款。

根据提示和当前实现，问题指向智能体/名称是否获得认证。当前使用官方公开的动态客户端注册；官方说明名称是显示元数据，可由用户调整，不是身份凭据。用户成功授权与对话证明这次接入可用，不证明 OpenAI 已审核或背书 ChatNote。[注册说明](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

目前确认到的官方联系渠道：[Request a client ID](https://developers.openai.com/siwc/request-client-id) 中的 Sign in with ChatGPT interest form。该渠道针对商用合作意向；付费/远程托管产品也应按官方指南确认接入形式。公开文档尚未说明一个自助“名称认证”按钮，或保证商用申请能消除此提示。[适用范围](https://developers.openai.com/siwc/token-sharing-open-source)

建议先准备下列材料，以便与官方沟通；这是项目准备建议，不是官方确认的完整申请要求：

- [ ] 说明 ChatNote 的维护者、联系方式、官网或项目主页。
- [ ] 明确个人本地、开源、私有或商业发布形式。
- [ ] 提供产品用途、演示和真实使用场景。
- [ ] 提供隐私说明与数据流：本地保存、发送哪些上下文、凭据保存方式。
- [ ] 整理应用标识、OAuth 回调、权限和注册/令牌生命周期设计。
- [ ] 向官方询问名称/开发者认证是否开放、所需材料，以及本地独立客户端的审核方式。
- [ ] 收到明确答复后记录结论；正式批准前保留第三方应用说明。

OpenAI 认证、Windows 安装包签名、商店审核分别记录，不能用其中一项替代另一项。
