# ChatNote 版本控制与发布

源码仓库：https://github.com/MKCorleonE/ChatNote ，Private。默认分支 `main`；当前已有源码以 v0.2.0 为首次基线。早期安装包仍保留，不伪造此前版本的源码提交。

## 日常升级

1. 在分支中完成一项功能/修复，检查差异并执行适用的测试。
2. 用有意义的提交保存改动，升级时同步版本、CHANGELOG_AND_IDEAS.md、FEATURES.md 与交付说明。
3. 将验证通过的工作合入 main 并推送。较大的修改使用 Pull Request 复核；用户要求的升级授权包含向本私有仓库同步相关源码，不能改为公开仓库。
4. 正式交付时打版本标签；构建安装包、记录 SHA-256，将包附在私有 Release 中。先完成附件上传与检查，再发布该 Release。

提交可比正式版本细：一次升级可以包含多个提交，推送代码不自动发布安装包。

GitHub Actions 使用只读仓库权限，检查前端测试/编译、Rust 格式和常规测试；两项写入系统凭据库的测试保持显式忽略。当前检查基于 Windows，不能视为其他平台验收。

## 文件范围

跟踪源码、测试、依赖锁文件、图标、文档与版本记录。忽略安装包、缓存、临时测试目录、.env、数据库及私钥；系统凭据库始终不在仓库里。原型和既有提案作为历史源码保留。

## 版本归档

常用 releases 目录保留最新版＋上一稳定版；更早版本归档。私有应用仓库的 Releases 需要仓库访问权限。2026-10-13用户明确授权新增[独立公开官网仓库](https://github.com/MKCorleonE/chatnote-site)，由其Pages与公开Releases提供网站和选定安装包；应用源码仓库保持私有。不改变原仓库公开性或增加合作者。

官网与公开下载独立维护，不能上传应用源码、私有开发材料、数据库、个人导出或历史总校验表。公开资产复制已交付程序原字节，逐版校验；下载与建站记录见[验证](WEBSITE_LAUNCH_VALIDATION.md)和[行动清单](GITHUB_PAGES_LAUNCH_PLAN.md)。

保存源码不等同于备份用户聊天；聊天数据库继续保存在本机，应用的完整工作区备份负责保存聊天与批注。
