# ChatNote 版本控制与发布

自2026-10-17起，用户明确授权将审查后的应用源码仓库 [MKCorleonE/ChatNote](https://github.com/MKCorleonE/ChatNote) 公开，采用 PolyForm Perimeter 1.0.1。这是限制竞争用途的源码可见许可，不宣传为 OSI 标准开源。默认分支 main。

## 仓库分工

- ChatNote：完整应用源码、Issue、PR、测试、版本标签和0.13.0起的正式 Release。安装包不进入 Git 源码历史。
- chatnote-site：官网、三语指南、静态更新清单；已有0.12.0/0.11.0下载附件保留为历史，不再重复上传新版本。每版下载元数据可指定不同发行仓库。

## 升级流程

1. 在 codex/ 或贡献者功能分支实现并同步三语、功能清单、版本记录和用户交付说明。
2. 运行前端测试/构建、Rust格式/原生测试和桌面打包；检查数据迁移、来源锚点、凭据保留、待安装更新恢复和失败路径。
3. 建立PR并等待Windows CI成功；核对最终头提交后合入main，版本标签必须与发布源码对齐。
4. 正式更新使用维护者私钥签名，公钥内置，签名绑定版本；私钥不进Git、网页、日志或PR。
5. 创建草稿Release，上传安装包、签名、该版公开校验表、latest.json及许可证材料；0.14.0起统一提供安装包，历史直接程序保留。核对远程大小/摘要后正式发布。
6. 最后更新官网版本数据及 updates/stable.json，匿名下载并验签。启动检查不调用模型、不附带聊天或连接凭据。

源码公开前检查全部历史文件、截图、构建日志和附件。普通升级保持已确定的可见性，未经明确授权不增加协作者或再次改变公开性。

开发贡献见 CONTRIBUTING.md，安全报告见 SECURITY.md。现有会话、草稿、附件、来源锚点、API凭据和ChatGPT注册必须保留。未跟踪的个人资料不因源码公开而自动提交。
