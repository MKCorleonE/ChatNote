## 使用

关闭旧开发窗口，并在它的启动命令窗口按 Ctrl+C 结束旧服务，再双击根目录 `启动开发预览.cmd`。底层网络代码需重新编译；只刷新界面无法保证正在使用新代码。无需退出账号，继续使用原聊天和系统凭据库。

先在设置中检查连接，再自行发送一次问题。检查只查询目录/认证，不生成回答，不自动消耗推理额度。若仍失败，展开“服务商详情”，记录新的固定错误码；不要粘贴任何密钥。

- 用户报告：同节点的 ChatGPT 桌面端可用；认证公钥页曾显示 ERR_CONNECTION_CLOSED，未换节点后恢复 JSON；随后 API 模型目录页显示缺少认证信息的 JSON。用户尚未确认本轮修复后的真实发送成功。
- 助手只读检查：最早错误为续期/签名公钥获取失败，后续错误已进入 API 连接阶段。运行中 Clash 是规则模式、TUN 开启，认证/API 请求确实进入同一代理节点；系统代理开关关闭不能单独解释 TUN 下的失败。
- 助手公共地址测试：Windows TLS 工具和 ChatNote 同款网络库多次遇到 TLS 握手 EOF/超时，同款库也曾取得 API 401。浏览器可访问与新的原生连接失败先后出现，证据支持间歇性连接异常，不能据此确定某一个节点、协议或代理规则是唯一根因。
- HTTP/2 与 TLS 1.2 对照未稳定消除异常；本轮不强制协议降级，不关闭证书验证，也不将 HTTP/2 作为已证实的修复。
- 源码确认原 reqwest 关闭默认功能却未启用 `system-proxy`。本轮显式启用系统代理支持，让 Windows 的已启用系统代理设置也能被使用；保留环境变量代理与 TUN 路径，不自动开启系统代理、不硬编码 Clash 端口。参见 [reqwest 官方功能说明](https://docs.rs/reqwest/0.12.28/reqwest/#optional-features)。本机原系统代理开关为关闭，不能把它作为本次恢复的唯一归因。

## 最终行为

- 认证公钥、会话续期、登录服务检查、模型目录和生成请求在**连接建立失败、HTTP 请求尚未发出**时最多尝试三次，等待 350 ms、1 s。证书验证失败不自动重试；记录仍留在原凭据库。
- 服务器 HTTP 错误、已发出请求后的网络中断、流式输出中断与结果不明的请求超时均不自动重发；保留原失败/部分回答行为。生成的 API 重连等待可以停止，不启动独立后台重试任务。
- 固定详情码区分 TLS 连接关闭、连接超时、DNS、证书和其他传输问题；不显示底层 URL、请求头或原始错误链。TLS 关闭提供英/简/繁三语恢复说明，历史错误文字不被改写。
- 持续连接失败时，三次尝试最坏可能略超过一分钟。此修复提高连接恢复能力，不能保证外部链路恢复，也不证明套餐授权、额度和真实生成均正常。
